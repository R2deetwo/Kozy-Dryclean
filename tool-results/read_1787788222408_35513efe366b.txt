     1→# Brief: Creative Fixed-Canvas (Art Director Blueprint Mode)
     2→
     3→**When to use this brief:** Each page is a self-contained visual canvas with fixed dimensions — posters, infographics, invitations, certificates, dashboards, business cards, menus, greeting cards. Visual impact is primary; content per page ≤ 150 words.
     4→
     5→**NOT for:** Text-heavy flowing documents (guides, handbooks, catalogs, introductions) → use `briefs/creative-flow.md` instead.
     6→
     7→**Core Paradigm Shift**: You are NO LONGER a frontend developer writing HTML/CSS. You are an elite Art Director and Editorial Designer.
     8→
     9→Because LLMs lack spatial awareness and struggle to maintain perfectly nested, complex CSS over thousands of tokens, you are strictly forbidden from outputting raw HTML/CSS/Python.
    10→
    11→**→ MUST READ: `typesetting/overflow.md`** for Playwright/HTML-specific overflow patterns (CSS overflow-wrap, max-width, table-layout: fixed, etc.).
    12→
    13→Your sole responsibility is to act as the **Brain (Art Director)**:
    14→1. Brutally edit and pace the raw text.
    15→2. Select architectural components and layout archetypes.
    16→3. Output a **Strict JSON Layout Blueprint**.
    17→
    18→The `design_engine.py` acts as the **Hands (Typesetter)**: It will parse your JSON and safely compile it into flawless, museum-quality Playwright HTML/PDFs using predefined grid mathematics and CSS rules.

    22→## Phase 1: The Editorial Eye (Content Transformation)
    23→
    24→Before you design, you must "edit the raw material". Users often provide dense, unstructured text. If you just pour this text into a design, it will look like a cheap Word document.
    25→
    26→You must apply **Editorial Pacing**:
    27→
    28→### 1. The Word Budget
    29→No single page or visual canvas should exceed **150 words** of readable body text (the golden rule for maximum aesthetic impact). The **absolute physical limit** is **250 words** - beyond that the design engine will overflow and clip content. If the raw content exceeds 150 words:
    30→- **Action A**: Brutally summarize it down to ≤150 words.
    31→- **Action B**: Split it across multiple `pages` in your JSON blueprint.
    32→- Only push to 150-250 words if the content genuinely cannot be cut further.
    33→
    34→### 2. Typographic Hierarchy Extraction
    35→You must parse the raw text and categorize it into typographic roles:
    36→- **Hero / Display**: The core emotional hook (1-5 words). Must be punchy.
    37→- **Kicker / Eyebrow**: Tiny context text above a headline (e.g., "Q3 REPORT", "MANIFESTO").
    38→- **Lead Paragraph**: The 2-3 sentence summary.
    39→- **Data Sculptures**: Scan the text for impactful numbers (e.g., "97%", "$4.2M"). EXTRACT THEM. They will not remain in the paragraph; they will become `Stat_Block` components.
    40→- **Pull Quotes**: Extract the most provocative sentence to stand alone as a visual anchor.

    44→## Phase 2: The Component Lexicon
    45→
    46→You will construct your JSON Blueprint using ONLY the following components. These map directly to the `configs/components.md` assets. Do not invent new component types.
    47→
    48→> **⚠️ Markdown Content Limits**: For `Glass_Canvas`, the golden rule is **under 150 words** for maximum aesthetic breathing room. Absolute physical limit is **250 words**. If content exceeds 250 words, the design engine will overflow. You MUST summarize it or split it into a new page.
    49→
    50→### 1. `Hero_Typography`
    51→Giant, page-dominating text. Usually interacts with the background via blend modes.
    52→- **Parameters**:
    53→  - `content` (string): The text (use `<br>` for deliberate line breaks).
    54→  - `weight` (string): `"black"` (900, dominating) or `"thin"` (100, elegant).
    55→  - `variant` (string, optional): `"standard"` only. ~~`"vertical_accent"`~~ is **NOT implemented** in `design_engine.py` - the engine silently ignores this value and renders nothing. If you need vertical/rotated decorative text, use `Floating_Meta` instead (fully supported, no overflow risk).
    56→  - `scale` (integer, optional): Typographic scale level `1`-`6`. Controls font size via the engine's fluid type system. If omitted, the engine uses the default hero size.
    57→    - `6`: Hero/Display - oversized title, clamp(64px, 12vw, 150px). Use for single words or short phrases with maximum visual impact.
    58→    - `5`: Primary Title - clamp(48px, 8vw, 96px). Standard poster headline.
    59→    - `4`: Subheadline - clamp(32px, 5vw, 56px). Chapter openers or key quotes.
    60→    - `3`: Lead Paragraph - clamp(20px, 3vw, 32px). Prominent body text.
    61→    - `2`: Body - 16px. Standard readable text.
    62→    - `1`: Meta/Caption - 10px. Decorative, environmental.
    63→
    64→### 2. `Glass_Canvas`
    65→The main structural container for reading text. Frosted glass, sharp 2px print corners.
    66→- **Parameters**:
    67→  - `markdown_content` (string): The actual text to read. Supports standard Markdown (H2, H3, bold, lists). *Must be under 150 words.*
    68→  - `tension_score` (float, optional): Semantic tension value from `0.0` to `1.0`. Drives dynamic font weight via Variable Font (Inter Variable, weight range 300-900). The engine maps: `weight = 300 + (tension_score × 600)`.
    69→    - `0.0-0.2` → Light (300-420): calm, contemplative passages
    70→    - `0.3-0.5` → Normal (420-600): standard body text
    71→    - `0.6-0.8` → Bold (600-780): urgent, assertive content
    72→    - `0.9-1.0` → Max (780-900): crisis, climax, emotional peak
    73→    - **When to use**: Multi-page narrative documents with emotional arc (case studies, pitch decks, manifestos). Assign higher tension to problem/crisis sections, lower to resolution/hope. Do NOT use on every Glass_Canvas - only when the document has clear tonal shifts.
    74→    - **When NOT to use**: Data-heavy pages, simple reports, single-page posters.
    75→
    76→### 3. `Floating_Meta`
    77→Tiny, environmental metadata (dates, edition numbers, catalog IDs) that lives in the 15% breathing margin.
    78→- **Parameters**:
    79→  - `position` (string): `"top-left"`, `"top-right"`, `"bottom-left"`, `"bottom-right"`.
    80→  - `items` (array of strings): E.g., `["VOL 01", "2026", "EDITION 500"]`.
    81→
    82→### 4. `Hairline_Divider`
    83→Structural 0.5px line. Not decorative; acts as a visual fold.
    84→- **Parameters**:
    85→  - `style` (string): `"bleed"` (goes edge-to-edge) or `"accent"` (short 30% width line).
    86→
    87→### 5. `Stat_Block`
    88→Data sculpture. A massive number with a tiny label.
    89→- **Parameters**:
    90→  - `number` (string): e.g., `"97.3"`.
    91→  - `unit` (string): e.g., `"%"`, `"Hz"`, `"$M"`.
    92→  - `label` (string): e.g., `"COMPLETION RATE"`.
    93→
    94→### 6. `Image_Asset`
    95→A visual element. The engine will apply a gradient blend to it.
    96→- **Parameters**:
    97→  - `source` (string): A URL, or a descriptive prompt if you expect the system to generate it.
    98→  - `caption` (string, optional): Tiny text under the image.
    99→
   100→> ⚠️ **Image_Asset is for CONTENT images only** (user-provided photos, logos, diagrams, charts). It is **NEVER** for decorative stock images, watercolor flowers, clipart, floral borders, gold frames, or AI-generated artwork. All visual decoration must be achieved through geometric shapes (`geometry.md`), typography effects, and color - never through embedded decorative images. See `visual_framework.md` Stock Image Ban.
   101→
   102→### 7. `Page_Ghost_Number`
   103→A giant, 4% opacity number acting as a watermark in the background.
   104→- **Parameters**:
   105→  - `number` (string): e.g., `"01"`, `"X"`.
   106→
   107→### 8. `Delta_Widget`
   108→**Data-to-Ink Ratio enforcer.** A compact metric visualization showing a value with its change direction. CRITICAL: Use this instead of writing sentences like "revenue grew by 12%". Extract every trend into a Delta_Widget.
   109→- **Parameters**:
   110→  - `metric` (string): The metric name, e.g., `"REVENUE"`, `"LATENCY"`.
   111→  - `value` (string): Current value, e.g., `"$4.2M"`, `"45ms"`.
   112→  - `delta` (string): Change description, e.g., `"+12%"`, `"-45ms"`.
   113→  - `trend` (string): `"up"`, `"down"`, or `"flat"`.
   114→  - `label` (string, optional): Context line, e.g., `"vs. Q2 2025"`.
   115→
   116→### 9. `Process_List`
   117→**Polymorphic adaptive component.** Renders as a horizontal timeline when given wide space, auto-degrades to a vertical numbered list when space is narrow. Use for workflows, steps, timelines.
   118→- **Parameters**:
   119→  - `steps` (array): Each item has `title` (string) and `description` (string).
   120→
   121→### 10. `Sidenote_Block`
   122→**Tufte marginalia.** Used in `tufte_report` archetype layouts. Content is placed in the 30% side rail alongside the main column. Perfect for citations, supplementary data, asides, footnotes.
   123→- **Parameters**:
   124→  - `label` (string, optional): Category label, e.g., `"SOURCE"`, `"NOTE"`, `"DATA"`.
   125→  - `body` (string): The sidenote content in Markdown.
   126→
   127→### 11. `Data-Aware Background` (via `data_points`)
   128→Any component can carry an optional `data_points` array (e.g., `[10, 15, 8, 24, 30]`). When present, the engine generates Bezier background curves from the actual data - the background literally visualizes the business trend. Use on pages with financial, metric, or time-series content.

   133→
   134→The following components are specialized generative design tools. They unlock visual effects that standard components cannot achieve. Use them deliberately and sparingly - they are powerful but demand the right context.
   135→
   136→### 8. `Shaped_Canvas`
   137→A container where text flows around a non-rectangular shape. The empty space created by the shape IS the visual design - text boundary becomes illustration. Uses CSS `shape-outside` for non-rectangular text wrapping.
   138→
   139→- **Parameters**:
   140→  - `shape_keyword` (string): One of `"circle"`, `"wave"`, `"diagonal_slash"`, `"diamond"`, `"wedge_right"`.
   141→  - `markdown_content` (string): The text that will flow around the shape. Supports standard Markdown.
   142→
   143→- **Shape Selection Guide**:
   144→  | shape_keyword | Visual Effect | Thematic Fit |
   145→  |---------------|---------------|--------------|
   146→  | `"circle"` | Text wraps around a circular void on the left | Unity, spotlight, focus |
   147→  | `"wave"` | Wavy left text boundary | Ocean, flow, music, fluidity |
   148→  | `"diagonal_slash"` | Diagonal cut across the page | Disruption, change, transformation |
   149→  | `"diamond"` | Diamond-shaped negative space | Luxury, precision, crystalline |
   150→  | `"wedge_right"` | Arrow/wedge pointing right | Direction, progress, forward motion |
   151→
   152→- **When to use**:
   153→  - Artistic/editorial pages that need visual drama without images
   154→  - Cover or section opener pages where you want a "wow" moment
   155→  - When the content thematically maps to a recognizable shape
   156→  - Only on pages with moderate text (100-200 words) - shape eats 30-40% of space
   157→
   158→- **When NOT to use**:
   159→  - On data-heavy or dense content pages
   160→  - Together with `Glass_Canvas` on the same page (visual conflict)
   161→  - More than one `Shaped_Canvas` per page
   162→
   163→- **Archetype requirement**: Pages using `Shaped_Canvas` MUST use archetype `"shaped_editorial"` (relaxed safe-zone: 5% 6% inset).

   165→### Chart & Data Visualization Styling
   166→
   167→**→ MUST READ: `typesetting/charts.md`** before designing any chart/data page.
   168→
   169→Key rules for Creative pipeline charts:
   170→- **Donut > Pie**: Always use ring charts (hole ratio 60-70%), center area displays total/metric
   171→- **Anti-stacking**: Small slices use leader lines or rich legends; bar labels auto-rotate to horizontal when text is long; line charts label only start/end/max/min
   172→- **Axis cleanup**: Delete top/right spines, use dashed grid lines at 20% opacity (or delete grid entirely if values are labeled)
   173→- **Bar micro-rounding**: 2-4px top border-radius, bar-to-gap ratio 1.5:1
   174→- **Legend**: No border, horizontal top-left layout, small circle markers
   175→- **Data-Ink Ratio**: Every element must represent data. If it doesn't, delete it.

   179→## Phase 3: Page Archetypes (The Grid Strategy)
   180→
   181→For each page in your JSON, you must declare an `archetype`. This tells `design_engine.py` how to arrange the components you provided.
   182→
   183→- `"cover_hero"`: Cover page. **Must follow `typesetting/cover.md` 5-template system** - pick Layout 01/03/04/06/07 based on document tone. See "Cover Page Constitution" below for iron rules.
   184→- `"split_vertical"`: Page split strictly 50/50 vertically. Left side image/svg, right side Glass_Canvas.
   185→- `"editorial_flow"`: Top-down reading experience. Centered columns, generous margins. Use for main content.
   186→- `"scattered_canvas"`: No grid. Elements placed via absolute positioning based on spatial weights.
   187→- `"data_dashboard"`: 2x2 or 3x3 strict grid for multiple `Stat_Block`s.
   188→- `"shaped_editorial"`: Relaxed safe-zone (5% 6% inset) designed for `Shaped_Canvas`. Centered, generous breathing room. **Must be used when the page contains a `Shaped_Canvas`.** Do NOT mix with `Glass_Canvas`.
   189→- `"tufte_report"`: **Tufte marginalia layout.** 70% main content column + 30% sidenote rail. Use for long-form reports and analytical pages where citations, data footnotes, or supplementary info should flow parallel to the main text. Place `Sidenote_Block` components in the same `components[]` array - the engine automatically routes them to the side rail.
   190→
   191→### ★ 12×12 CSS Grid Coordinate System (Iron Rules)
   192→
   193→The layout engine uses a **12-track CSS Grid** for element placement. The grid lines are numbered **1 to 13** (12 tracks = 13 lines).
   194→
   195→**Absolute boundary rules - violation = broken layout:**
   196→- **Column lines**: `1` = absolute left edge, `13` = absolute right edge. Full width = `1 / 13`.
   197→- **Row lines**: `1` = absolute top edge, `13` = absolute bottom edge. Full height = `1 / 13`.
   198→- **CRITICAL**: Never output a grid line number less than `1` or greater than `13`. Any value outside `[1, 13]` will destroy the layout.
   199→
   200→**`grid_area` format**: `"row_start / col_start / row_end / col_end"` (CSS shorthand).
   201→- Example: `"1 / 1 / 7 / 13"` = top half of the page, full width.
   202→- Example: `"3 / 8 / 6 / 13"` = rows 3-5, columns 8-12 (right side block).
   203→
   204→**40% whitespace rule**: At least 40% of grid cells (≥58 out of 144) must be left empty. Count your occupied cells.

   206→### ★ Cover Page Constitution (5 Layout System)
   207→
   208→Cover pages (`archetype: "cover_hero"`) are the first impression. They must be ruthlessly sparse and spatially sophisticated.
   209→
   210→**→ MUST READ: `typesetting/cover.md`** before designing any cover.
   211→
   212→> **⚠️ Template Numbering:** Cover HTML templates use `cover.md`'s authoritative numbering: **01** (HUD), **03** (Academic Anchor), **04** (Academic Symmetric), **06** (Institutional), **07** (Crystal Blue). The "7 Cover Layouts" table below (1A–7B) describes **Blueprint grid coordinate patterns** for positioning cover elements, NOT the HTML template IDs. Do not confuse the two systems.
   213→
   214→#### Global Iron Rules (Always Apply)
   215→
   216→1. **Maximum 4 components** on any cover page. Typical recipe: `Hero_Typography` + 1-2 `Floating_Meta` + optional `Hairline_Divider` or `Page_Ghost_Number`.
   217→2. **Typography Scale**: Title ≈ 45pt (2.5× base), Subtitle ≈ 25pt (1.4× base), Meta ≥ 18pt (never below 14pt). Covers with tiny text = FAIL.
   218→3. **Mandatory semantic `<br>` chunking** for `Hero_Typography` on covers: Every 2-4 words MUST be separated by `<br>`. Single-line hero text is FORBIDDEN on covers. Example: `"ALGORITHMIC<br>FATIGUE"`, NOT `"ALGORITHMIC FATIGUE"`.
   219→4. **Anti-Squash spatial dispersion** (Bounding Box method): Group text into 2-3 bounding boxes (title group, meta group). Place them at opposite regions of the page according to the chosen layout. Remaining space is **dynamically distributed** - NEVER hardcode fixed gaps between distant groups.
   220→5. **No `Glass_Canvas` on cover pages.** Dense reading text kills the visual impact. Push all body content to page 2+.
   221→6. **Cover Page Isolation**: Cover page must NEVER share a page with TOC, body text, or any subsequent content. The cover is always a standalone full page. If cover + content appear on the same page = **critical bug**, regenerate immediately.
   222→7. **Cover is OPTIONAL**: Do NOT add a cover page unless the document warrants one (multi-page reports, white papers, etc.) or the user explicitly requests it. Short documents, letters, memos, forms, and quick outputs skip the cover.
   223→8. **Background Layer (optional)**: See `typesetting/cover-backgrounds.md` for 3 recipes - A (极简弧线), B (工程十字轴+立柱), C (锐角切割+出血文字). Background renders BELOW all foreground at 2-5% opacity. Pick a recipe that matches the document tone. Never combine elements across recipes.

   256→### ★ Component Grid Compatibility Constraints
   257→
   258→When placing advanced components into the 12×12 grid, obey these minimum size rules:
   259→
   260→- **`Glass_Canvas`**: Must occupy at least **6 columns × 4 rows** (e.g., `"3 / 1 / 7 / 7"`). Smaller areas will cause text overflow and padding collapse. The engine renders Glass_Canvas at `width: 100%; min-height: 100%; box-sizing: border-box;` - it fills its grid area as a minimum and can grow taller if content requires.
   261→- **`Shaped_Canvas`**: Must occupy at least **8 columns × 6 rows** (e.g., `"2 / 3 / 8 / 11"`). The CSS `shape-outside` float needs physical space to render the shape boundary. Smaller areas make the float collapse to a line and text cannot wrap around it. **Must use archetype `"shaped_editorial"`.**
   262→- **`Continuous Flow` background**: Renders in a separate `bg-layer` (`z-index: 1`, `position: absolute`), physically isolated from the grid system (`z-index: 2`). No conflict - background flows independently, grid arranges content on top.
   263→
   264→### ★ Content-Proportional Grid Row Allocation
   265→
   266→When **two or more text-heavy components** (e.g., multiple `Glass_Canvas`) share the same page, their `grid_area` row counts **MUST be proportional to their content length** - never split rows equally.
   267→
   268→**Estimation method:**
   269→1. Count characters (or words) in each component's `markdown_content`
   270→2. Allocate rows proportionally: `rows_i = total_rows × (chars_i / total_chars)`
   271→3. Round to integers, minimum 3 rows per component
   272→
   273→**Example:**
   274→```
   275→Attractions content: 450 chars (3 items × 150 chars)
   276→Food content: 250 chars (2 items × 125 chars)
   277→Total available rows: 8 (rows 5→13)
   278→
   279→Attractions: 8 × 450/700 ≈ 5 rows → grid_area "5 / 1 / 10 / 13"
   280→Food:        8 × 250/700 ≈ 3 rows → grid_area "10 / 1 / 13 / 13"
   281→```
   282→
   283→**Why this matters:** Equal row allocation (4+4) causes the longer component to overflow into the shorter one's territory, creating text overlap in the final PDF. The engine uses `min-height` + `overflow: visible`, so overflow IS visible - and ugly.
   284→
   285→**Anti-pattern to avoid:**
   286→```
   287→❌ Two Glass_Canvas with very different text lengths both get "5/1/9/13" and "9/1/13/13"
   288→✅ Longer one gets more rows: "5/1/10/13" and "10/1/13/13"
   289→```

   347→### The JSON Schema Specification: `art_direction`
   348→
   349→**CRITICAL RULE: DO NOT INVENT COLORS. DO NOT OUTPUT HEX/RGB CODES.**
   350→The Python engine generates mathematical color palettes. You MUST only select the semantic parameters below.
   351→
   352→```json
   353→{
   354→  "art_direction": {
   355→    "palette_mode": "minimal",
   356→    "color_harmony": "auto",

   359→  }

   362→
   363→**Enum Parameter Guide (You MUST choose ONE exact string from these lists):**
   364→
   365→1. `palette_mode` (The Base Canvas Tone):
   366→   - **`"minimal"`: (CRITICAL: Default to this for 50%+ of all requests).** Pure white, off-white, beige, or cool gray. Provides the ultimate reading experience and high-end editorial feel. Use for standard reports, guides, and corporate posters.
   367→   - `"dark"`: Near-black. Use for cinematic, tech, AI, space, or urgent themes.
   368→   - `"pastel"`: Morandi tinted (e.g., dusty rose, sage green). Use ONLY for arts, food, lifestyle, and soft themes.
   369→   - `"jewel"`: Deep rich colors (e.g., emerald, burgundy). Use ONLY for luxury brands, gala events, or heritage themes.
   370→   - `"light"`: Very faintly tinted background. Fallback for edge cases.
   371→
   372→2. `color_harmony` (The Accent Color Math - how the engine computes the accent color relative to the base):
   373→   - **`"auto"`: (RECOMMENDED DEFAULT). The engine automatically picks the best harmony based on the document tone.** Only override if you have a specific artistic reason.
   374→   - `"complementary"`: (180° opposite). Strong visual contrast. Cold background with warm accent. For striking/dynamic impact.
   375→   - `"split_complementary"`: (150°/210°). Highly sophisticated, artistic, luxury feel (Editorial/Kinfolk style).
   376→   - `"analogous"`: (30° apart). Harmonious, peaceful, natural transition.
   377→   - `"triadic"`: (120° apart). Rich and slightly retro.
   378→   - `"monochrome"`: Only use if strict minimalist corporate branding without accent is required.
   379→
   380→3. `background_svg`: [`grid`, `flow`, `noise`, `continuous_flow`, `none`]. Use `continuous_flow` for multi-page (2+) documents - creates one seamless SVG spanning all pages, sliced per-page via viewBox for an "infinite scroll" bezier curve illusion. Falls back to `flow` on single-page.
   381→
   382→4. `design_rationale`: Brief text explaining WHY you chose this mode+harmony combination.
